## 1. 研究目标

本项目面向智能算法在装备实装验证中的应用需求，开展智能算法黑盒测试与综合评估技术研究，重点解决深度学习模型可解释性不足、第三方算法实现细节不可获取、训练数据与部署环境存在分布偏移等工程现实难题。与传统白盒验证依赖源码审计、结构分析和训练过程复现不同，黑盒测试将被测算法视为由"输入—运行约束—输出"共同定义的可观测系统，通过规范化输入控制、多场景样本注入和输出语义解析，验证算法在未知数据、复杂环境与极端边界条件下的泛化能力、鲁棒性和工程适配性。

在装备论证和试验鉴定过程中，智能算法来源复杂，可能由不同研制单位以模型文件、推理服务、可执行程序或容器镜像形式交付。此类算法即使具备较高的试验室指标，也可能由于数据域差异、目标尺度变化、遮挡噪声干扰、传感器成像链路变化和硬件资源约束，在外场条件下出现误检、漏检、延迟过高或输出格式不稳定等问题。因此，本课题将黑盒测试定位为算法实装前的关键工程环节，建立不依赖算法源码和内部结构的第三方客观评估手段。

本研究结合重大装备故障检测和故障预测与健康管理（PHM）的应用背景[31]，目标是构建一套系统化、可复用、可追溯的智能算法黑盒测试与综合评估技术路线，并依托一套已工程落地的微服务化测试平台予以验证。该路线以典型图像分类和时序预测算法为主要对象，覆盖 YOLO、ViT、R-CNN、LSTM、TCN、Informer 等六类代表性模型，围绕算法性能、模型复杂度和算法特性三个层级建立分级量化指标体系，形成从算法接入、容器化部署、样本输入、任务执行、语义解析、综合评分到报告生成的自动化闭环。

研究成果应能够支撑被测算法在未知样本、复杂电磁与光照条件、极端气象、低信噪比和资源受限等条件下的可靠性验证，为后续模型精调、结构压缩、样本补强和工程部署提供定量依据。通过该技术路线，可将智能算法从"单一准确率验收"推进到"多维指标、分层场景、闭环反馈"的综合评估模式，为实装应用提供工程可行性和风险可控性支撑。

## 2. 研究内容

### 2.1 研究内容描述

本项目将智能目标识别、图像分类和装备状态时序预测等典型任务中的被测算法抽象为"输入—运行—输出"系统，在不获取源码、不干预模型内部推理过程的前提下，通过外部可控输入和可观测输出来完成算法能力画像。该视角将黑盒算法由不可解释对象转化为可实验对象，使测试系统能够围绕输入分布、场景条件、资源约束和输出质量建立稳定的评价逻辑。

**输入端**：研究多样化基准数据集与扰动样本集构建方法。基准数据集覆盖舰船、车辆、机场设施、雷达站、道路桥梁等典型军事目标类别，并按目标尺度、成像角度、遮挡比例、背景复杂度、气象条件、光照条件和传感器类型分层组织。扰动样本集围绕噪声叠加、分辨率下降、压缩失真、运动模糊、局部遮挡、伪装纹理和低对比度条件构建，用于验证模型对分布外样本和极端边界条件的适应能力。

**任务设计**：对 YOLO 和 R-CNN 类目标检测算法，重点设计边界框定位、类别识别、置信度校准、小目标发现和密集目标分离任务；对 ViT 类图像分类算法，重点设计类别判别、类间混淆、背景偏置和遮挡鲁棒性任务；对 LSTM、TCN 和 Informer 类时序模型，重点设计设备运行数据预测、异常趋势识别、长序列依赖建模和时间漂移适应任务。

**评价层**：从算法性能、模型复杂度、算法特性三个维度进行分级量化评估。算法性能刻画准确率、精确率、召回率、F1、mAP、AUC、预测误差等指标；模型复杂度刻画参数规模、推理时延、吞吐量和输入层宽度等工程指标；算法特性刻画小目标检测能力、类内变化适应度、噪声敏感度、细节损失机理、置信度稳定性和输出规范性。

上述研究内容最终汇聚为一套"数据驱动的多维量化综合评估与全景测试报告自动生成闭环"。测试平台通过轻量化容器沙箱隔离运行被测算法，利用可编程流式数据规范化路由向容器注入测试样本和模型文件，动态监听算法输出并进行多维语义解析，将异构预测结果转化为统一元数据，进而由后台数学模型完成指标计算、评分融合和报告生成。

### 2.2 技术要求及指标

#### 2.2.1 技术要求

1. 提出适用于智能目标识别、图像分类和时序预测算法的黑盒测试总体方案，覆盖 YOLO、ViT、R-CNN、LSTM、TCN、Informer 等六类典型算法，能够在不依赖算法源码和训练过程信息的条件下完成测试；
2. 构建标准化测试流程与评分机制，形成数据集接入、任务配置、容器部署、输入注入、输出解析、指标计算、综合评级和报告生成的闭环流程，测试结果满足可复现、可追溯、可审计要求；
3. 采用基于 Docker 的轻量化微服务沙箱隔离环境，对被测算法运行依赖、文件系统、网络访问和日志输出进行规范化管理，确保第三方算法接入过程具备安全隔离和资源可控能力；
4. 构建可编程流式数据规范化路由机制，对模型文件、图像样本、时序数据、配置参数和任务脚本进行自动校验、格式对齐和静态/动态注入，保证不同算法在统一输入条件下接受测试；
5. 构建多维语义输出自动化解析与推理提取引擎，能够解析边界框、类别标签、置信度张量、分割掩膜、时序预测值、日志文本和异常返回码，并统一映射为标准化评估元数据；
6. 算法提交形式需满足格式要求：至少提供可执行入口、依赖说明、输入输出协议、运行参数说明和容器化构建文件；对不满足接口规范的算法给出异常指标和整改建议。

#### 2.2.3 指标解释

本节采用"符号说明—核心公式—适用对象—工程含义"的方式组织。所有公式以黑盒测试可观测数据为基础，不要求获取算法源码、训练过程或内部网络结构；当模型结构可读时，复杂度指标可由结构解析获得，否则由容器运行时测量和输入输出行为统计获得。

**表 2-2 指标公式符号说明**

| 符号 | 含义 | 适用对象 |
|---|---|---|
| N | 测试样本总数 | 全部算法 |
| K | 目标类别数 | YOLO、ViT、R-CNN |
| TP/FP/FN/TN | 真阳性/假阳性/假阴性/真阴性 | 检测、分类、告警任务 |
| B_p、B_g | 预测框、真实框 | YOLO、R-CNN |
| y_t、ŷ_t | 真实时序值、预测时序值 | LSTM、TCN、Informer |
| T | 时序长度或预测步数 | 时序预测算法 |

**(1) 分类与目标检测基础指标**

$$Accuracy = \frac{TP+TN}{N},\quad F1_k = \frac{2 \cdot Precision_k \cdot Recall_k}{Precision_k + Recall_k}$$

对于类别不均衡的军事目标样本，应优先关注宏平均 F1 和关键类别召回率，避免大量常见类别掩盖少数高价值目标的漏检风险。

**(2) 边界框定位与平均精度指标**

$$IoU = \frac{S_{overlap}}{S_{union}},\quad mAP = \frac{1}{K}\sum_{k=1}^{K} AP_k$$

mAP@0.5 偏重目标发现能力，mAP@0.5:0.95 更强调定位精度和框形态一致性。

**(3) ROC 曲线与告警判别指标**

对于关键目标告警任务，应重点关注低 FPR 区间的 TPR；AUC 用于跨阈值比较整体告警能力，但不应替代关键阈值下的任务指标。

**(4) 时序预测误差与趋势一致性指标**

$$MAE = \frac{1}{T}\sum_{t=1}^{T}|y_t - \hat{y}_t|,\quad RMSE = \sqrt{\frac{1}{T}\sum_{t=1}^{T}(y_t - \hat{y}_t)^2},\quad TrendAcc = \frac{N_{trend\_correct}}{N_{trend\_total}}$$

数值误差较小但趋势方向错误仍可能影响预警判断，应将误差指标与趋势指标联合使用。

**(5) 模型复杂度与运行资源指标**

$$Params = \sum_l |\theta_l|,\quad Latency_{avg} = \frac{1}{M}\sum_{i=1}^{M}(t_{end,i} - t_{start,i}),\quad Throughput = \frac{M}{t_{end} - t_{start}}$$

若模型结构不可解析，则以容器运行时的时延、显存峰值、CPU/GPU 利用率和吞吐量作为复杂度替代指标。

**表 2-3 六类算法指标适配关系**

| 算法类型 | 主要指标 | 复杂度关注点 | 工程解释 |
|---|---|---|---|
| YOLO | mAP、AP_small、Recall、F1 | 输入分辨率、检测头尺度、后处理耗时 | 适合实时检测，需重点验证小目标和密集目标能力 |
| R-CNN | mAP@0.5:0.95、定位误差、Recall | 候选框数量、骨干网络参数量、ROI 处理耗时 | 定位精度较强，但需关注推理时延和资源占用 |
| ViT | Accuracy、Macro-F1、AUC、校准误差 | Token 数量、注意力层数、嵌入维度 | 适合全局语义判别，需测试背景偏置和遮挡敏感度 |
| LSTM | MAE、RMSE、TrendAcc、异常召回率 | 隐状态维度、时间步长、门控参数量 | 适合中短期序列建模，需关注长序列误差累积 |
| TCN | MAE、RMSE、趋势一致性 | 卷积核大小、膨胀因子、感受野 | 并行效率较好，需验证感受野是否覆盖关键历史窗口 |
| Informer | 长序列 MAE、异常提前量、趋势召回率 | 序列长度、稀疏注意力采样、编码层数 | 适合长序列预测，需关注缺测和采样间隔变化条件 |

### 2.3 问题描述与分析

深度学习模型黑盒特性与实装可靠性验证之间存在突出矛盾。一方面，深度神经网络通过大规模参数、非线性激活和层级特征抽象获得强表达能力；另一方面，其决策过程难以被传统规则解释，且工程交付场景中常常无法获取源码、训练数据、模型结构细节和超参数配置，导致测试人员难以采用白盒方式确认模型在关键条件下的失效边界。

在未知数据条件下，算法可能遭遇训练阶段未覆盖的目标外形、传感器视角、背景纹理和场景组合。对于军事目标识别，舰船舷角变化、车辆伪装涂装、机场设施局部遮挡、海面浪纹和地物阴影均可能改变模型输入分布。若评估仅停留在同源测试集准确率上，模型可能表现出较高的名义指标，却在外场样本上出现召回率骤降或置信度虚高。

在复杂环境下，算法性能还受到光照、气象、电磁干扰、图像压缩、链路延迟和平台运动等因素影响。此类失效往往不是单一指标能够揭示的，需要通过分层场景测试和专项特性分析才能定位。在极端边界条件下，算法失效可能呈现非线性突变——目标尺寸低于若干像素阈值时小目标 AP 突然下降，遮挡比例超过一定范围时模型从正确识别转为高置信误检，输入序列长度超过训练窗口时时序模型产生累积误差。此类失效边界决定了算法在任务链路中的使用条件和风险告警策略。

因此，本课题必须采用不依赖源码和内部结构的黑盒检测方法：通过控制输入、记录运行过程、解析输出和统计结果，将不可见的内部机制转化为可观测的外部行为分布。只要输入样本、任务条件、运行环境和输出协议被规范化，测试系统即可在不同算法之间建立公平比较。

## 3. 国内外研究现状

随着人工智能在侦察监视、目标识别、态势感知和装备健康管理等领域的应用深化，智能算法测试与评估技术逐渐由传统软件测试扩展到数据驱动模型验证[27][28]。国内外研究均认识到，深度学习算法的测试对象不仅包括程序逻辑，还包括训练数据分布、模型结构、推理硬件、输入扰动和输出决策边界。

### 3.1 通用黑盒测试与智能软件测试研究现状

传统黑盒测试源于软件工程领域，强调在不了解程序内部实现的情况下，根据需求规格、输入域划分和输出判定准则设计测试用例[1][30]。等价类划分、边界值分析、因果图和状态迁移测试等方法为智能算法测试提供了方法论基础。对于深度学习模型，输入空间高维连续且语义复杂，传统手工测试用例难以覆盖关键失效区域，因此研究者将覆盖率、变异测试和搜索式测试引入神经网络评估。

Pei 等人提出的 DeepXplore[2] 首次将神经元覆盖率引入深度学习测试，通过梯度引导生成能覆盖更多神经元激活状态的测试输入。Ma 等人的 DeepGauge[3] 进一步提出多粒度覆盖率准则（神经元级、层级、组合级和边界级），为衡量测试集对模型内部行为的触达程度提供了量化指标。虽然此类指标更接近白盒/灰盒测试，但其思想对黑盒评估有启发：测试集不应仅追求数量规模，而应覆盖模型可能出现决策变化的关键区域。对无法读取内部激活的黑盒模型，可通过输入扰动、输出置信度变化和错误模式聚类近似刻画行为覆盖。

深度学习变异测试通过对模型结构、权重、训练数据或输入样本施加可控变异，观察测试集能否发现模型行为变化[4]。在黑盒条件下，测试平台无法直接修改被测模型参数，但可对输入样本进行语义保持扰动（亮度变化、噪声叠加、尺度缩放、局部遮挡），形成面向外部行为的变异测试框架。

对抗样本测试是国外研究中发展较快的方向。Goodfellow 等人[5] 和 Szegedy 等人[6] 的工作表明，深度神经网络对人眼难以察觉的扰动高度敏感，黑盒攻击方法甚至可在不知道模型梯度的条件下通过查询输出构造对抗样本[7]。虽然装备鉴定的目标不是攻击算法而是识别风险边界，但对抗测试思想能够帮助评估模型在极端输入扰动下的稳定性、置信度校准能力和异常输入拒识能力。Hendrycks 和 Dietterich[8] 提出的通用扰动基准为鲁棒性评估提供了标准化样本集。

在评估标准和工具链方面，国外围绕 COCO[9]、ImageNet[10] 等公共基准形成了较成熟的目标检测和分类评估协议，mAP、AP_small、AP_medium、AP_large 等指标具有较高通用性。PyTorch[11]、Detectron2[12]、MMDetection[13] 和 pycocotools 等工具链支持快速计算模型输出指标和复杂度信息，为自动化评估提供了工程基础。Calibration 研究[14] 推动了置信度校准评估方法的发展。

### 3.2 国内智能算法与军事目标识别评估技术发展现状

国内在智能算法评估方面已形成较为丰富的应用研究基础，特别是在遥感图像目标检测、舰船识别、车辆识别、SAR 图像解译、光电侦察图像处理和装备状态预测等方向积累了大量专用数据集和评测经验。与通用互联网视觉任务相比，军事目标识别更关注低分辨率、小样本、弱纹理、复杂背景和任务风险约束，因而需要更贴近实际应用场景的黑盒测试体系。

在专用数据集评估方面，国内研究逐渐从单一公开数据集训练验证转向任务场景化样本构建。通过结合卫星遥感、无人机影像、仿真生成数据和设备运行数据，可形成覆盖多平台、多视角、多气象、多尺度的测试样本库。该方向的优势在于能够将算法评估与具体装备任务绑定，但仍需进一步解决标注规范统一、样本分层均衡、跨域验证和评估结果可复现等问题。

在弱项精调指导方面，国内工程实践常将测试结果用于模型迭代，例如针对小目标漏检增加高分辨率切片样本、针对夜间目标误检补充低照度训练数据、针对时序预测滞后调整窗口长度和损失函数。此类方法实用性强，但若缺少统一评分模型和输出解析规范，弱项定位容易依赖专家经验，难以形成可持续的自动化闭环。

总体来看，国内外在智能算法黑盒测试方面仍存在若干共同挑战：一是黑盒条件下难以确认模型内部失效机理，需要通过外部行为统计构建可信解释[15]；二是不同算法输出格式差异较大，边界框、标签、置信度、日志和时序结果需要统一语义；三是测试样本空间巨大，必须在有限资源下优先覆盖高风险场景；四是综合评分需要兼顾任务性能、工程复杂度和环境鲁棒性，避免单一指标误导算法选型[16]。

本课题的研究定位是在上述背景下，面向军事智能算法实装评估需求，将通用黑盒测试理论、深度学习鲁棒性评估方法、目标检测指标体系和容器化工程实施机制结合起来，形成可落地的综合评估平台技术路线。

## 4. 智能算法黑盒测试关键技术研究

### 4.1 算法性能指标测试

算法性能指标测试是黑盒评估的基础层，目标不是简单给出一个总体准确率，而是从识别正确性、漏检风险、误报风险、定位精度、置信度稳定性和阈值可调能力等方面形成完整性能画像。对于军事目标识别任务，错误类型具有明显的任务含义：漏检关键目标造成态势遗漏，误检非目标造成资源误分配，定位偏差影响后续打击或跟踪，置信度虚高削弱人工复核机制。

准确率适用于类别均衡、输出类别互斥的分类任务。然而军事目标数据集类别分布往往不均衡，某些关键目标样本数量少而任务价值高，单一准确率容易被大量背景或常见目标样本掩盖。因此测试系统需同时计算宏平均 F1、类别召回率和混淆矩阵，以识别少数类目标是否被系统性误判。精确率反映模型输出为某类目标时的可信程度，召回率反映真实目标被发现的充分程度；二者在目标检测任务中存在典型权衡——降低置信度阈值可提升召回率但引入更多误报，提高阈值可降低误报但可能漏掉低质量成像目标。黑盒测试需在多个阈值上统计指标曲线，而非仅给出默认阈值结果。

F1 值是精确率与召回率的调和平均，适用于需同时控制误报和漏检的场景。对于海面舰船、机场目标、地面车辆等识别任务，F1 值能够反映模型在发现能力和判读可信度之间的平衡。ROC 曲线和 AUC 指标适合评价二分类或告警型目标识别任务；对于关键目标告警系统，低假阳性率区间的 TPR 尤为重要。目标检测中的 mAP 指标将类别识别、定位精度和置信度排序综合起来，是 YOLO 和 R-CNN 类模型的核心评价指标[9][29]。对于小目标和密集目标，定位误差对 mAP 影响更大，因此需分尺度统计 AP_small、AP_medium、AP_large。

对于 LSTM、TCN 和 Informer 类时序预测算法，性能测试从数值误差和任务行为两方面展开。MAE 和 RMSE 描述预测值与真实值之间的偏差，趋势准确率描述模型对上升、下降、稳定和突变状态的识别能力，异常召回率描述设备状态异常是否被提前捕获。

黑盒性能测试还需关注置信度校准[14]。一个高质量算法不仅应在正确样本上输出高置信度，还应在困难样本、分布外样本和低质量样本上表现出适当不确定性。若模型在错误预测上仍给出高置信度，会增加人工复核难度。测试平台可通过可靠性图、期望校准误差（ECE）和错误样本置信度分布对输出可信性进行量化。

### 4.2 模型复杂度测试技术

模型复杂度测试是连接算法性能与工程部署的重要环节。深度学习模型可能在离线服务器上取得较高精度，但在实装平台上受到算力、功耗、显存、存储、启动时间和通信带宽限制。如果复杂度评估不足，算法可能在仿真环境中通过验收，却在任务系统中无法满足实时性和稳定性要求。

参数规模是模型复杂度的基础指标，直接影响模型文件大小、加载速度和存储占用。对于卷积模型，参数量由卷积核尺寸、输入输出通道数和层数决定；对于 Transformer 模型[17]，参数量主要由嵌入维度、注意力头数、前馈网络宽度和层数决定；对于 LSTM 模型[18]，门控结构使参数量与输入维度和隐状态维度呈二次相关。输入层宽度决定模型能够接收的信息粒度——目标检测模型若输入分辨率较低，小目标细节可能在预处理阶段被抹除；若分辨率过高，推理时延和显存占用快速上升。

在工具层面，modelsummary 类工具可用于对可加载模型进行结构摘要，输出层级结构、参数量、输入输出尺寸和估算计算量。当模型结构可解析时，FLOPs 可按层级累加估算：对卷积层 FLOPs_l = 2·H_out·W_out·(C_in·k²)·C_out（H_out、W_out 为输出特征图高宽，C_in/C_out 为输入输出通道数，k 为卷积核尺寸），对 Transformer 自注意力层 FLOPs ≈ 4·d²·L + 2·d·L²（d 为嵌入维度，L 为序列长度）；当模型结构不可解析时，则以模型文件大小、加载时间、运行时资源曲线和输入尺寸敏感性为主，通过行为层测量反推复杂度量级。黑盒测试中，当被测算法提供模型文件但不提供源码时，可通过受控加载脚本在容器内部读取模型元信息；当模型仅以服务形式提供时，则通过推理探针统计批量大小、输入尺寸和时延变化，形成行为层复杂度估计。pycocotools 是目标检测评估中常用的指标计算工具[9]，其核心价值在于提供标准化的 COCO 格式解析、IoU 匹配、AP 计算和分尺度统计能力。Detectron2[12] 类工具链提供了模型推理、数据集注册、评估器和可视化分析等工程思想——平台构建适配器层，把算法输出转换为标准 Instances 对象或等价元数据，再由统一评估器完成统计。

复杂度测试还应覆盖运行时指标。平台在容器沙箱中对 CPU 占用、GPU 显存峰值、GPU 利用率、IO 吞吐、平均推理时延、P95 时延、批处理吞吐量和异常退出次数进行采集。由于黑盒算法可能隐藏内部实现，复杂度测试采用多路径证据融合：若模型结构可读，以参数量和 FLOPs 为主；若结构不可读，以模型文件大小、加载时间、运行时资源曲线和输入尺寸敏感性为主；若算法以远程服务形式提供，以查询延迟、吞吐稳定性和输出成功率为主。

### 4.3 算法特性专项测试

算法特性专项测试面向复杂军事环境下的特定风险点，重点分析算法在常规指标之外的失效模式。与通用性能测试相比，专项测试更强调场景约束和边界条件。

**小目标检测能力**：遥感图像和远距离光电图像中的舰船、车辆、雷达阵地等目标常常只占据少量像素。YOLO 类模型若特征金字塔设计不足或下采样过强，可能在高层语义特征中丢失小目标；R-CNN 类模型若候选框生成尺度不匹配，也会导致小目标召回率下降。测试系统按目标像素面积分层统计 AP，并分析漏检样本的尺度分布。

**类内变化适应度**：军事目标存在多型号、多批次、多姿态、多载荷状态和多伪装涂装，类内差异可能显著大于通用数据集。黑盒测试通过型号子类、视角区间、姿态区间和背景区间分层统计指标，识别模型是否只学习到少量典型外观。

**噪声敏感度测试**[8]：在保持标注不变的情况下，对样本叠加高斯噪声、椒盐噪声、压缩失真、运动模糊和低对比度变换，观察性能指标随扰动强度变化的曲线。若模型在轻微扰动下性能骤降，则说明其特征依赖过于脆弱。

**遮挡与伪装测试**：按遮挡比例、遮挡位置和遮挡纹理进行组合实验，统计模型在遮挡增加过程中的召回率和置信度变化，判断模型是否具备部分证据推理能力。

**复杂背景测试**：构建背景负样本库，统计每平方公里或每千帧虚警数量。对于军事任务，虚警不仅影响指标，还会消耗人工判读和后续传感器调度资源。

**长序列稳定性**：对 LSTM[18]、TCN[19] 和 Informer[20] 模型构造不同长度、不同缺测率和不同噪声水平的时序样本，评估模型预测误差随时间增长的变化，并记录异常预警提前量和漏警率[32]。

**输出规范性**：检查边界框是否越界、类别编号是否存在、置信度是否归一化、时序预测长度是否一致，以及异常返回码是否可解析。

### 4.4 标准化测试流程与综合评分机制

标准化测试流程是保证评估结果可复现和可比较的前提。平台首先完成被测算法注册，记录算法名称、版本、提交单位、运行入口、输入输出协议和资源需求；随后完成测试任务配置，选择数据集分层、指标集合、扰动强度、容器资源配额和输出格式；然后进入容器化执行阶段，平台向沙箱注入样本并监听输出；最后由解析引擎形成标准元数据并计算指标。

综合评分机制需兼顾性能、复杂度和特性三个层面的不同量纲。设第 q 个原始指标为 z_q，经正向或逆向归一化后得到 norm(z_q)。对于越大越好的指标（如 mAP、召回率、F1），采用线性归一化；对于越小越好的指标（如时延、显存、误差），采用反向归一化；对于存在阈值要求的指标，采用分段函数，使低于安全阈值的结果受到更强惩罚。权重设置结合层次分析法（AHP）[21]、熵权法和任务风险权重进行确定。AHP 通过构造同层指标间的两两比较判断矩阵 A=(a_ij)_{n×n}（a_ij 取 1~9 标度，a_ji=1/a_ij），求解最大特征值 λ_max 对应的特征向量 W 并归一化作为权重向量；为避免主观判断不一致导致权重失真，需计算一致性指标 CI=(λ_max−n)/(n−1) 与一致性比率 CR=CI/RI（RI 为随机一致性指标，n≥3 时 RI 取值 0.58~1.45），当 CR<0.1 时认为判断矩阵满足一致性要求。熵权法利用指标数据的离散程度赋权：第 q 项指标的信息熵 E_q=−(1/ln m)·Σ p_ij·ln p_ij（p_ij 为样本归一化值），信息熵越小则该指标区分度越高、权重 w_q=(1−E_q)/Σ(1−E_q) 越大。平台将 AHP 的主观权重与熵权法的客观权重按 0.5 系数融合，并叠加任务风险系数（如关键目标召回率在告警任务中风险系数 ×1.5），形成最终权重模板，避免单一赋权法的主观或数据依赖偏差。

#### 4.4.1 指标归一化、权重确定与红线约束

正向指标归一化：

$$S_q^+ = 100 \cdot clip\left(\frac{z_q - L_q}{U_q - L_q}, 0, 1\right)$$

逆向指标归一化：

$$S_q^- = 100 \cdot clip\left(\frac{U_q - z_q}{U_q - L_q}, 0, 1\right)$$

综合评分模型：

$$S_{total} = \sum_{q=1}^{Q} w_q S_q - \lambda \cdot N_{red} - \mu \cdot N_{abnormal}, \quad \sum_{q=1}^{Q} w_q = 1$$

其中 L_q 和 U_q 分别为第 q 项指标的合格阈值和优秀阈值，N_red 为红线指标数量，N_abnormal 为一般异常指标数量，λ 和 μ 为惩罚系数。该模型能够同时表达连续评分和强约束风险，使测试结论更符合工程准入逻辑。

分级量化评估采用优秀、良好、合格、受限可用和不建议使用五级。综合评分不掩盖单项高风险问题——平台采用"常规评估 + 红线指标"双层机制：常规评估用于排序和总体判断，红线指标用于触发强制风险提示。若算法出现越权访问、容器异常逃逸、关键目标召回率低于红线、输出不可解析或长序列预测发散等问题，即使大部分指标效果较好，也应在报告中标注为高风险并限制使用条件。

#### 4.4.2 输出异常、失败样本与弱项定位方法

黑盒测试的一个重要价值在于发现算法在正常指标之外的异常行为。传统评估往往只统计预测正确与否，而工程化平台还需记录空输出、重复输出、非法坐标、字段缺失、类别映射错误、置信度越界、日志报错、进程超时和资源溢出等异常。

失败样本分析采用样本标签和错误类型双索引机制。平台对每个失败样本记录场景标签、目标尺度、遮挡比例、背景类型、扰动强度、预测结果和真实标注，并将错误划分为漏检、误检、类别混淆、定位偏差、置信度异常和输出协议异常。通过统计错误在不同标签上的聚集程度，可判断模型弱项是否集中于某类环境。

**表 4-1 黑盒测试异常类型与处置建议**

| 异常类型 | 识别方式 | 工程影响 | 建议处置 |
|---|---|---|---|
| 输出不可解析 | 字段缺失、格式不合法、坐标越界 | 指标无法计算，系统接口无法集成 | 修订输出协议或增加适配器 |
| 关键类别漏检 | 重点目标召回率低于红线阈值 | 态势感知遗漏，任务风险升高 | 补充弱项样本并调整检测尺度 |
| 高置信误检 | 错误预测置信度显著偏高 | 人工复核压力增大，自动告警失真 | 开展置信度校准和难负样本训练 |
| 资源失控 | 显存溢出、超时、CPU 占用异常 | 无法稳定部署或影响并发任务 | 模型压缩、批量控制和资源配额优化 |
| 长序列发散 | 预测误差随时间持续扩大 | 装备状态预警失效 | 增加状态校正、外生变量和滑动更新机制 |

平台对失败样本建立回灌机制。经专家确认的失败样本进入弱项样本库，在下一轮模型训练或评估中作为重点样本使用——这是黑盒测试从一次性测评走向持续质量改进的重要资产。在报告表达上，弱项定位提供"问题描述—证据样本—量化影响—可能原因—改进建议"的链式结构。

## 5. 项目实施方案

### 5.1 总体技术方案

本项目总体技术方案采用基于轻量化容器沙箱的解耦式黑盒检测架构，将被测算法、测试数据、执行环境和评价模型分层隔离。平台已工程落地为基于 Spring Cloud 微服务架构的多租户系统，整体由观测/输入层、数据/样本层、检测执行层和评级反馈层构成，各层之间通过标准化接口传递任务配置、样本数据、运行日志和评估元数据。

**平台工程架构**（已实现）：系统采用 Spring Boot 4.x + Spring Cloud 微服务框架，划分为 10 个核心服务——网关（Gateway）、认证、模型管理、数据集管理、训练服务、评测服务、资源调度、对象存储、通知和审计监控。各服务通过 Nacos 进行服务注册与发现，通过 RabbitMQ 实现事件驱动通信（采用 Outbox 模式保证"DB 更新 + 消息投递"的一致性），通过 PostgreSQL（行级安全 RLS 实现多租户隔离）和 SeaweedFS（S3 兼容对象存储）进行数据与文件持久化，前端基于 Vue 3 + Element Plus 构建。被测算法的执行节点上部署一个 Go 语言编写的 Agent，通过 WebSocket 长连接接入平台，接收任务指令并回传实时日志、指标和结果。

**"每个模型 = 一个容器"契约**：被测算法以 Docker 镜像 tar 形式存入对象存储，平台资源调度服务为其预签名 S3 下载 URL，由 Agent 拉取、`docker load` 后以标准挂载（数据集只读、输出可写）和标准环境变量（`AISYS_TASK`、`AISYS_DATASET_DIR`、`AISYS_OUTPUT_DIR`、`AISYS_HYPERPARAMS` 等）启动。容器入口脚本遵循统一的 JSONL 输出协议（`status`/`log`/`metric`/`result` 四类帧），Agent 逐行解析后通过 WebSocket 实时回传，平台经 MQ 转发至对应服务进行持久化与计算。该契约使异构算法（不同框架、不同依赖、不同语言）在统一输入输出条件下接受公平测试，且算法研制单位无需暴露源码。

- **观测/输入层**：接收测试任务、算法提交包、模型文件、数据集描述和资源约束，进行格式校验、完整性校验和安全扫描。
- **数据/样本层**：管理高仿真军事目标基准数据集、扰动样本库、背景负样本库和设备运行时序数据，维护场景标签、难度标签、目标尺度标签、环境标签和标注版本，通过分层索引机制按任务需求抽取测试子集。
- **检测执行层**：采用 Docker 容器构建异构算法动态运行时，通过资源配额、目录挂载、网络策略和进程监控实现物理安全与计算资源隔离；Go Agent 经 WebSocket 接收任务、流式回传 JSONL 输出，微服务化调度支持任务队列、日志监听和异常恢复。
- **评级反馈层**：将边界框、类别标签、置信度、时序预测值和日志文本解析为统一元数据，调用指标计算模块生成性能、复杂度和特性测试结果，由综合评分模块给出等级评定，报告模块自动形成全景测试报告和弱项迭代建议。

### 5.2 黑盒检测全流程实施细则

#### 5.2.1 被测算法选择与容器化动态部署

被测算法选择阶段依据任务类型确定算法接入类别：目标检测任务优先接入 YOLO 和 R-CNN 类算法，图像分类任务优先接入 ViT 类算法，时序预测任务优先接入 LSTM、TCN 和 Informer 类算法。平台为每类算法提供统一接口规范——输入目录、配置文件、输出目录、日志目录和退出码规则。算法提交单位无需暴露源码，但必须提供可执行入口、依赖说明和容器化构建文件（Dockerfile）。

容器化动态部署阶段将待测智能算法封装入标准沙箱环境。平台基于 Docker 镜像构建算法运行时，自动对齐 Python 版本、CUDA 版本、深度学习框架、系统库和模型文件路径等异构依赖。对于已有镜像的算法，平台进行镜像签名校验、基础漏洞扫描和入口命令验证；对于仅提供压缩包的算法，平台根据依赖说明生成临时构建脚本并完成镜像封装。Agent 内置镜像缓存（按 imageName 索引，`docker image inspect` 命中即跳过重复下载/加载），避免每次任务重复拉取 2GB+ 的镜像 tar。

沙箱隔离策略包括文件系统隔离（被测算法只允许访问挂载的输入目录、输出目录和只读模型目录）、网络访问控制（默认关闭外网，仅授权情况下开放指定地址）、资源配额（CPU、GPU、内存、显存和运行时间均设上限）和运行生命周期管理。容器启动后，平台执行打包规则检查，确认算法进程是否按约定接收参数、读取测试样本、在指定目录输出结果。健康检查失败时记录镜像启动日志、依赖错误、缺失文件和权限异常，作为工程适配异常写入报告。

#### 5.2.2 检测任务选择与可编程流式输入控制

检测任务选择由任务编排模块完成。平台根据算法类型自动推荐测试组合：YOLO 模型默认执行 mAP、分尺度 AP、置信度校准、小目标、遮挡、噪声和推理时延测试；ViT 模型默认执行准确率、混淆矩阵、遮挡敏感性、背景替换和输入分辨率敏感性测试；Informer 模型默认执行长序列误差、异常趋势召回和缺测鲁棒性测试。

可编程流式数据规范化路由是输入控制的关键。平台将基准数据集、模型文件、配置参数和测试脚本按任务序列注入容器运行时——输入路由不仅复制文件，还进行类别映射、标注格式转换、数据切片、批次组织和校验摘要生成。每次输入注入均记录样本 ID、场景标签、扰动强度、时间戳和容器任务编号，保证结果可追溯。

对于图像与视频样本，支持两种注入模式：一是将数据集打包进镜像（适用于离线批量评估），二是通过容器挂载技术动态挂载数据集（平台据此验证算法在连续输入、突发高负载和空目标帧条件下的稳定性）。对于时序数据，进一步提供滑动窗口生成、缺失值注入、采样间隔扰动和长序列切片等数据构造功能。

#### 5.2.3 检测实施与多维语义输出自动化解析

检测实施阶段由任务调度器向容器沙箱下发任务命令，并同步启动资源监控和日志监听。Agent 通过 WebSocket 长连接实时回传容器的 JSONL 输出（`status` 帧更新进度、`log` 帧记录日志、`metric` 帧携带每 epoch 的指标、`result` 帧携带终态结果），平台经 RabbitMQ 转发至训练/评测服务持久化——日志写入 `task_log` 表、指标写入 `task_metric` 表（JSONB 存储，支持任意指标 key）、结果触发综合评分。该实时回传机制使前端监控页能够滚动显示训练日志、绘制指标曲线并展示下载按钮，而非等到任务结束才给出结论。

多维语义输出自动化解析与推理提取引擎是连接黑盒输出与数学评估模型的核心。不同算法可能输出 TXT、JSON、CSV、二进制张量、图片标注或日志文本。解析引擎通过适配器识别字段含义，将边界框坐标统一转换为 `[x_min, y_min, x_max, y_max]` 格式，将类别名称映射为统一类别 ID，将置信度归一化到 [0,1] 区间，将时序预测结果对齐到标准时间索引。若算法输出缺少字段、坐标越界、类别编号不存在或置信度为非法值，平台记录为输出协议异常；若容器出现依赖报错、显存溢出、超时退出或空输出，记录为运行异常——异常不丢弃，而作为工程可靠性指标进入综合评分。

为保证解析结果可信，平台对每个输出元数据建立来源链路（原始输出文件、解析适配器版本、样本 ID、容器任务 ID、指标计算版本），后续报告中的每一个指标均可追溯到具体样本和原始输出，满足科研试验和工程验收对可审计性的要求。

#### 5.2.4 综合评级、报告生成与迭代优化闭环

综合评级阶段对性能、复杂度和特性三类指标进行归一化处理，依据任务权重模板计算子项得分和总分。报告生成模块自动形成数据驱动的多维量化综合评估全景测试报告，内容包括算法基本信息、容器运行环境、测试数据集组成、测试任务列表、性能指标、复杂度指标、专项特性指标、异常记录、综合评分、等级结论和整改建议。对于关键弱项，报告给出样本示例、指标下降曲线和可能原因分析，而非仅给出结论性分数。

迭代优化闭环面向算法改进：若算法未满足评级要求，平台根据弱项类型给出改进方向（小目标能力不足时建议增加高分辨率切片训练；噪声敏感时建议开展数据增强和稳健训练；时延过高时建议进行模型剪枝、量化或输入尺寸优化；时序预测漂移时建议调整窗口长度、引入外生变量或采用分段建模）。优化后的算法重新封装为容器并进入下一轮测试，平台通过版本管理比较不同轮次的指标变化，判断改进是否真实有效。

### 5.3 基于军事目标图像样本集的检测验证

**图 5-2 基于军事目标样本集的检测验证流程**（此处插入图：展示样本分层组织、典型测试任务编排、全景测试报告生成的全流程）

本课题拟构建军事目标图像样本集和设备运行数据集开展检测验证。图像样本集覆盖舰船、装甲车辆、机场设施、雷达阵地、桥梁道路、港口设施等典型目标，按光学遥感、近距可见光、红外图像和仿真生成图像进行来源标注。每个样本除目标类别和边界框外，还标注目标尺度、遮挡比例、背景复杂度、成像角度、光照条件和气象条件。

测试场景设计包括常规清晰场景、海面复杂背景场景、港口密集目标场景、低照度场景、云雾遮挡场景、小目标远距离场景、压缩传输场景和空目标背景场景。输入流设计采用"任务配置 + 样本批次 + 扰动参数"的组合方式。输出流要求算法在指定目录生成标准结果文件（目标检测算法输出目标框、类别和置信度；分类算法输出类别概率或 Top-K；时序预测算法输出预测时间戳、变量值和可选置信区间）。

**表 5-1 检测验证场景与输入输出流设计**

| 场景 | 输入内容 | 输出内容 | 重点评价指标 |
|---|---|---|---|
| 常规清晰目标 | 标准分辨率图像、完整标注框 | 类别、边界框、置信度 | mAP、F1、置信度校准 |
| 小目标远距离 | 目标面积低于阈值的切片样本 | 小目标预测框集合 | AP_small、漏检率、定位误差 |
| 遮挡伪装 | 局部遮挡、伪装纹理、低对比度样本 | 遮挡条件下预测结果 | 召回率下降曲线、错误类型 |
| 复杂背景负样本 | 港口、海岸线、道路、建筑阴影等无目标样本 | 空目标或低置信输出 | 虚警率、非法输出率 |
| 长序列设备数据 | 多变量运行数据、缺失值、采样间隔变化 | 预测序列、异常告警 | MAE、RMSE、趋势召回率 |

验证结果形成多层次对比：同一算法在不同场景下的性能对比、不同算法在同一数据集上的横向对比、同一算法不同版本之间的迭代对比、以及性能指标与复杂度指标之间的效费比对比。通过这些对比，项目可识别适合实装的算法类型、部署约束和后续优化方向。

#### 5.3.1 样本分层组织与标注质量控制

军事目标图像样本集的建设坚持任务牵引、场景分层和质量可控。样本不仅覆盖目标类别，还覆盖目标出现方式——以舰船目标为例，同一类别在不同舷角、不同海况、不同分辨率和不同背景下呈现的视觉特征差异明显。样本库在目标、环境和成像链路三个维度建立标签体系。

标注质量控制是测试可信度的基础。目标检测标注需明确边界框贴合规则、截断目标处理规则、密集目标分离规则和忽略区域规则。平台设置标注复核流程，对关键类别、小目标和边界模糊样本进行二次审核并记录标注版本。样本分层避免单一场景过度占比——平台在报告中给出样本分布表（目标类别分布、尺度分布、背景分布、光照分布、遮挡分布、扰动强度分布），只有在样本分布透明的前提下，指标结论才具有解释力。

#### 5.3.2 典型测试任务编排与执行控制

典型测试任务编排采用分阶段执行：第一阶段为接口适配测试（验证算法能否在容器中启动、读取输入、输出标准结果）；第二阶段为基准性能测试（使用清晰样本计算主指标）；第三阶段为专项特性测试（逐项注入小目标、遮挡、噪声和低照度样本）；第四阶段为压力测试（评估长时间运行、批量输入和资源约束下的稳定性）。

执行控制保证测试隔离——每个测试批次在独立容器或清理后的容器环境中运行，防止缓存、临时文件和状态变量影响后续结果。任务编排支持失败恢复：若某个测试批次因容器异常退出而失败，平台记录失败样本、失败时间、日志和资源状态，并根据策略决定是否重试；重试结果与原始失败记录同时保留，避免异常被重试过程掩盖。

#### 5.3.3 全景测试报告内容与工程应用方式

全景测试报告围绕"结论可读、证据可查、建议可执行"的原则组织。报告首页给出算法总体评级、关键红线、主要优势和主要短板；正文按数据集、任务、指标和场景展开；附录保存详细样本清单、运行日志摘要和指标计算配置。

报告支持版本对比：平台将同一算法不同版本的指标放在同一视图下，显示哪些指标改善、哪些指标退化、是否出现新的异常，防止模型在优化某一弱项时引入新的风险。在工程应用上，全景测试报告可作为算法准入、型号选型、试验鉴定和后续精调的共同依据。

## 6. 项目创新点

**第一，系统化"输入—输出"系统视角的智能算法黑盒测试路线创新。** 将黑盒算法视为受控输入、约束运行和可观测输出共同构成的外部行为系统，通过输入域分层、扰动样本设计、输出语义解析和指标统计建模，在不依赖源码和内部结构的条件下评估算法能力边界。这一思路适合第三方算法交付、模型文件不可解释和运行依赖复杂的工程场景。

**第二，基于轻量化容器沙箱与可编程数据路由的工程实施方案创新。** 以 Docker 容器处理黑盒算法为技术事实基础，将其升华为异构算法动态容器运行时和微服务沙箱隔离环境，配合"每个模型 = 一个容器"的标准化镜像契约与统一 JSONL 输出协议，实现未知算法依赖解耦、运行安全隔离和计算资源动态调度。平台通过可编程流式数据规范化路由，将模型文件、基准样本、扰动参数和任务脚本精准注入沙箱运行时，使不同算法在统一输入条件下接受公平测试。

**第三，算法性能、模型复杂度、算法特性三位一体的分级量化评估指标体系创新。** 不仅评价准确率、召回率、F1 和 mAP 等性能指标，还将参数量、FLOPs、显存占用、推理时延、吞吐量等复杂度指标纳入工程可用性判断，并设置小目标、噪声、遮挡、类内变化、细节损失和长序列稳定性等专项特性指标，形成面向实装的多维能力画像。

**第四，多维语义输出自动化解析与推理提取机制创新。** 构建输出适配器和标准元数据模型，将边界框、类别标签、置信度张量、日志文本、时序预测值和异常返回码统一转化为可计算指标，解决黑盒算法"能运行但难评价"的工程痛点，使异构算法输出能够进入统一数学评估模型。配合"常规评估 + 红线指标"的双层评分机制，避免单一综合得分掩盖关键缺陷。

**第五，基于弱项评级的模型迭代优化闭环创新。** 将测试报告从静态验收文档扩展为算法改进指南，通过分层场景指标、异常样本定位和评分权重分析指出模型弱项，并为数据补强、模型精调、结构压缩和阈值校准提供定量依据。优化后的算法重新进入容器化测试，形成持续迭代闭环。

## 7. 后续规划

后续将进一步提升测试平台自动化水平，重点完善算法提交包自动解析、容器镜像自动构建、任务模板自动匹配、输出适配器自动识别和报告自动生成能力，减少人工配置环节。对于常见算法框架，平台将沉淀标准适配器；对于新型算法，平台将提供低代码配置方式，使测试人员能够快速定义输入输出映射和指标计算规则。

后续将扩充极端边界条件样本库，围绕小目标、强遮挡、低照度、烟雾云雾、海面反光、压缩传输、运动模糊、伪装纹理、复杂负样本和长序列缺测等高风险条件，持续构建分层样本集。样本库建设坚持真实数据、仿真生成数据和扰动合成数据结合，既保证场景覆盖又保证标注质量和可控变量。

后续将加强评估模型的可解释性辅助。虽然黑盒测试不依赖内部结构，但评估结果仍需具备可解释性[15]。平台通过错误样本聚类、置信度分布分析、遮挡敏感性曲线、场景标签关联分析和复杂度效费比分析，帮助研制人员理解模型失效原因。对可读取中间信息的灰盒对象，可进一步引入特征可视化和注意力热力图作为辅助证据。

后续将完善多任务、多模型横向对比能力，支持同一数据集下多个算法并行测试、同一算法多版本回归测试和不同硬件资源配置下的部署测试，形成算法选型矩阵。最终目标是支撑智能算法从研制验证、第三方测评到实装准入的全流程质量控制，并推动评估规范固化与工程应用验证。
